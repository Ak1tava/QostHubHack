## Решения и общий контракт

- Голос нужен мастеру в описании нового наряда и исполнителю в описании выполненных работ. Пользователь редактирует расшифровку и отдельно вставляет её в форму; запись не сохраняет/не отправляет наряд и не меняет статусы.
- Модель: Whisper large-v3-turbo через faster-whisper; отдельный ASR-процесс, без OpenAI API и платных вызовов. CPU int8 — переносимый режим; CUDA float16 допускается после реальной проверки. Модель загружается отдельной командой, не при запросе пользователя; отсутствие модели/сервиса даёт понятный 503.
- Публичный API: `POST /api/v1/speech/transcriptions`, multipart `file`, `language=ru|kk`. Только вошедшие master/worker, прежние session/CSRF. Ответ: `SpeechTranscription { text: string, language: 'ru'|'kk', model: 'large-v3-turbo', duration_seconds: number, is_mock: boolean }`. Ошибки через существующий ErrorResponse: 401/403, 413 размер, 415 формат, 422 язык/пустое/некорректное/слишком длинное аудио, 429 занят/лимит, 503 недоступность. Cache-Control no-store.
- Лимиты: 60 секунд, 10 MiB; реальный контейнер и декодированная длительность проверяются сервером. MIME: audio/webm, audio/mp4, audio/x-m4a, audio/mpeg, audio/wav, audio/x-wav, audio/ogg; допустимые codec-параметры отделяются от MIME. Декодирование ограничивается 60 секундами плюс порог обнаружения превышения, произвольные пути/URL не принимаются. Аудио только временное, не в БД/логах/истории; cleanup при ошибке/отмене.
- Внутренний ASR API: `POST /transcribe` с теми же multipart полями, Bearer-токен из `settings.speech_service_token`; `GET /health/ready`. Сервис слушает loopback или внутреннюю Docker-сеть, порт 8016 не публикуется наружу. Один inference одновременно, второй получает 429; backend без автоматического повтора, timeout 90 секунд. Модель загружается лениво из заранее подготовленного локального каталога, запросы ничего не скачивают.
- Корневые настройки: `speech_service_url: str|None=None`, `speech_service_token: SecretStr|None=None`, `speech_request_timeout_seconds=90`, `speech_model_path: Path|None=None`, `speech_device='cpu'`, `speech_compute_type='int8'`. Без настройки ASR остальное приложение работает как раньше. Fake провайдер только через тестовую подмену зависимостей.
- Telegram: plain text до безопасного лимита; тип события, номер, русский приоритет, оборудование/участок, исполнитель/бригада, срок в settings.app_timezone; для просрочки прошедшие минуты и последний доступный комментарий; понятное действие и существующая HTTPS-кнопка. Не выводить UUID/job state/исключения, не добавлять команды Telegram, не менять интервалы/дедупликацию/lease/отмену.
