## Shared T12 contract (frozen before agent dispatch)
- `GET /api/v1/work-orders/templates`, authenticated, no-store; static route BEFORE `/{order_id}`. Response `WorkOrderTemplateList {items: WorkOrderTemplate[]}`.
- `TemplateId`: `visible_leak` or `visible_element`. `WorkOrderTemplate`: id, version (positive integer), title, initial_description, instructions:string[], checklist:`{id,label,required:boolean}[]`, photo_requirements:`{before:int,after:int}`.
- Both definitions version1, exactly3 required checklist items, before1/after1. Titles: «Устранение видимой течи», «Восстановление видимого элемента». Leak checklist ids: `identify_leak`, `describe_repair`, `inspect_result`; element ids: `identify_element`, `describe_restoration`, `inspect_result`. Labels concern visible location, described work and visual inspection only; never certify hidden condition or safe operation.
- `WorkOrderCreate.template_id: TemplateId|null = null`; arbitrary client snapshot is forbidden. Server resolves definition and stores a fresh JSON object on creation, never on replay.
- `WorkOrderView.template_snapshot: WorkOrderTemplate|null = null`. `WorkOrderDetail.before_photo_count:int =0` counts authorized stored before photos of THIS order (including master's issuance photo). Existing worker before-upload UI reloads this count.
- `SubmissionCreate.template_answers: TemplateAnswer[] =[]`, each `{id:string,checked:StrictBool}`; `SubmissionView.template_answers` returns saved answers. Unknown/duplicate ids, missing required/false answers or insufficient photos →422, no report/material/event/outbox/receipt side effects. Legacy orders accept only empty answers.
- Before evidence: stored Photo with matching work_order_id/type before; after evidence: existing validation for matching order/current uploader/unbound after_photo_ids. No foreign photo acceptance. Required counts apply on submission, not initial order creation (before uploads occur after create).
- DB: WorkOrder.template_snapshot nullable JSON; Submission.template_answers non-null JSON default[]; migration0006 after0005 (upgrade/downgrade). Existing report_view includes persisted answers and missing template evidence so downstream human acceptance cannot bypass requirements.
- Frontend: default «Без шаблона»; selected definition fills an empty/previously template-filled description, preserves user's own text; selecting/removing template never resets QR area/equipment or voice draft. Show instructions/checklist/photos in creation, execution and saved report. Respect command pending/retry locks. Sending template reports blocked until all required checks and photo counts, backend remains authoritative.
