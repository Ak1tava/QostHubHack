# T08/T10: утверждённый план реализации

Основа: main 99929ba. Пользователь 2026-10-07 утвердил параллельную работу трёх агентов в отдельных worktree, первый мобильный прогон на двух iPhone, временный HTTPS-туннель и дополнительный лимит живого ИИ $2.

## Общие ограничения

- Публичные статусы только в plans.md; локально проверенный код REVIEW, DONE после main и обязательной живой приёмки.
- T08: существующие данные, Q/T, R/V и неподтверждённые коррекции «нет данных», веса доступных компонент нормируются. Без новых миграций/форм учёта рейтинга, CSV и платных сводок.
- Доступ проверяется сервером до агрегирования; worker не видит чужие оценки даже в своей бригаде. Числа SQL/Python, исходный эталон аномалий только в тестах.
- Секреты, реальные персональные данные и производственные фотографии вне Git. Никаких оплаченных API в автоматических тестах.
- T10: Telegram UI, до пяти before-фото мастера при выдаче, временный Cloudflare Quick Tunnel, безопасная цепочка proxy, сохранность БД/фото, budgeted ai-worker.
- Живой тест на двух iPhone; отдельный Android обязателен до закрытия R01. Создание ≤60 с/≤6 действий, события ≤5 с, фото ≤10 с на измеренной мобильной сети; критерии нельзя заменять эмуляцией.

## Задачи

1. Сервер T08: три API C1, период [start,end), отчёт смены, исторические счётчики/интервалы, рейтинг принятого отчёта, три вычисляемые закономерности, PostgreSQL behavioral tests.
2. Web T08: три страницы с общей фильтрацией, типы из OpenAPI, объяснение компонентов/размера выборки и ссылки на доказательства; Vitest. Навигация/контракты централизованно интегратором.
3. T10: Telegram UI и R02, tunnel overlay/runbook, сохраняемый ограниченный ai-worker $2, behavioral tests; без VPS/домена и без реального запуска внешних интеграций до готовности стенда.
4. Интеграция: общие контракты, lifecycle/permissions E2E, чистая сборка/миграции/recovery, материалы сдачи (8 слайдов, резервное видео ≤3 мин, демо 7 мин), проверка и короткая передача работы.

## Приёмка

Проверить полночь/границы, прошлую просрочку, объединение простоя, revision/reassignment, отсутствие данных, нормирование, аномалии T09 и права. Затем Vitest/typecheck/build, настоящее PostgreSQL API/PWA E2E без retries, контракты и recovery. Физические телефоны/Telegram/оплаченный worker фиксируются отдельно, только по фактическому результату.

## Исходные решения

Ruling: агенты работают параллельно по явному утверждённому плану пользователя; зоны файлов разделены, общие контракты и интеграция принадлежат A/Codex.
Ruling: облачный HTTPS-туннель выбран вместо production VPS. Обязательная работа компьютера и смена URL после перезапуска входят в runbook.
