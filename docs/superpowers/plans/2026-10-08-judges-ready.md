# Подготовка НарядAI к проверке судьями

Утверждено пользователем в чате 2026-10-08. Владелец: A / Codex; база main e5e4afc; ветка codex/judges-ready. Исполнение: Superpowers subagent-driven-development, три независимых worktree.

## Требования
- Три кнопки входа: Мастер, Рабочий 1, Рабочий 2. Judge-only серверный режим выключен по умолчанию, фиксированные пользователи из одной судейской группы; существующие сессии, CSRF/Origin, rate limit и права сохраняются.
- GET /api/v1/auth/judge-profiles -> {profiles:[{code,display_name,role}]}; коды master, worker-1, worker-2. POST /api/v1/auth/judge-login {profile:code} -> прежний AuthResponse. При выключенном режиме endpoints возвращают 404. Клиент не получает пароль/произвольный user_id.
- Второй рабочий добавляется идемпотентно в существующую группу, без reset прежних пользователей, паролей, нарядов и назначений.
- Смена профиля отзывает прежнюю сессию, сбрасывает клиентское состояние/WS и открывает домашний экран роли.
- Основные экраны RU/KZ очищаются от T18, MOCK и повторяющихся служебных надписей. Неизменяемые отчёты/фото/ИИ-результаты не переписываются; меняется отображение известных подготовленных данных. Один бейдж «Подготовленный результат», происхождение в подробностях.
- ИИ-проверка и решение мастера выше истории. Вывод, доказательства, недостающие сведения и следующее действие видны сразу; до отчёта объясняется запуск проверки.
- AIReviewView.source: provider|rules|prepared|mock|unknown, сервер вычисляет из сохранённых данных. provider требует завершённого реального вызова с response_id и без error_code; не выводится только из is_mock=false. Миграция не нужна.
- Текущий Windows-компьютер: восстановить PostgreSQL, API, Whisper, Nginx, notification/review workers и HTTPS. Сохранить исходные фото/БД/ledger; общий лимит $10 не сбрасывать. Учесть штатное завершение review-worker через сутки, повторять только безопасно с тем же ledger.
- Подготовить backup перед live mutations; развернуть проверенный commit, пройти новый отчёт через настоящий GPT и решение мастера, проверить сохранность после restart. VPS и анализ истории оборудования не входят.

## Задачи и владельцы
1. Auth agent: services/api/app/modules/auth, core/config, отдельная подготовка профилей, соответствующие тесты. Не менять generated contracts и plans.md.
2. UI agent: apps/web и UI/E2E tests; потребляет контракт auth выше и AIReviewView.source. Не менять backend/generated contracts/plans.md.
3. Runtime agent: infra/native_runtime.py и runtime/budget tests; восстановление исходного PostgreSQL и изолированные тестовые БД. Live deployment выполняет основной агент.
4. Основной агент: вычисление AI source и тесты, последовательная генерация OpenAPI/TS, интеграция, независимое ревью, проверки и live release.

## Приёмка
- Изоляция ролей/двух рабочих; CSRF, disabled mode, invalid profile, session rotation/logout; идемпотентная подготовка.
- UI/Vitest/E2E: три кнопки, смена профиля, RU/KZ, подготовленные/правила/реальные/ошибочные результаты; build/contracts.
- Реальный HTTPS report->photo->GPT->master, проверка response_id и прежнего ledger; нет авто-CLOSED или повторного списания.
- Restart сохраняет данные и ledger. Физические мобильные замеры не заявляются. В plans.md обновлять только T10/T18 и необходимый CURRENT_STATE; до интеграции REVIEW.
