# T13: формат и доставка Telegram

Владелец: A / Codex + агент Telegram; ветка `codex/t13-t16-delivery`. Проверка проводится только с синтетическими данными и fake transport; живые отправки и webhook не запускаются.

Текст уведомления содержит событие, номер наряда, русский приоритет, оборудование, участок, актуального исполнителя либо бригаду с ответственным, срок в `settings.app_timezone` и действие в PWA. Просрочка дополнительно показывает полные прошедшие минуты и последний непустой комментарий текущего назначения: причина перехода либо комментарий отчёта. Чужой наряд, прежнее назначение, JSON payload и служебные ошибки в текст не попадают. Отсутствующий комментарий обозначается явно.

Plain text отправляется без `parse_mode`: HTML и команды внутри комментария остаются данными. Управляющие и форматирующие Unicode-символы удаляются; переносы и пробелы входных полей сворачиваются в один пробел. Поля ограничены независимо, поэтому длинный комментарий не вытесняет срок и действие; суммарный текст укладывается в 3500 единиц UTF-16. Inline HTTPS-кнопка `Открыть наряд` ведёт на существующий `/orders/{id}`.

Pipeline сохраняется: PWA выдаёт одноразовый токен → `/start` в личном чате → webhook с секретом и дедупликацией update → binding. Изменение наряда сохраняет audit + outbox в одной транзакции; consumer фиксирует receipt и задания с прежними dedup key, интервалами и отменой устаревших назначений. Worker получает lease, повторно проверяет актуальность/доступ, блокирует rows только на подготовку, фиксирует попытку до сетевого вызова и завершает delivery с fencing token. 403 завершает job как FAILED, 429 соблюдает retry_after; backoff, лимит попыток и восстановление lease после restart остаются прежними. Доставка at-least-once: crash/timeout после принятия сообщения Telegram может дать повтор.

Кнопка открывает HTTPS PWA; вход и серверные права остаются обязательными. Принятие, отчёт и закрытие выполняются в PWA. Автотесты fake transport подтверждают содержимое/URL и серверные гарантии, но не проверяют открытие Telegram in-app browser, сессию на телефоне, сеть или реальную доставку ботом. Эти проверки требуют отдельной живой приёмки.

Проверка 2026-10-08: выделенный Python 3.12 runtime и отдельная PostgreSQL `qosthub_test_t13_20261008`; `python -m pytest tests/test_telegram_format.py tests/test_telegram_review_fixes.py tests/test_t06_integration.py tests/test_telegram_client.py tests/test_telegram_linking.py tests/test_telegram_delivery_visibility.py tests/test_telegram_recovery.py tests/test_deadlines.py -q -p no:cacheprovider --tb=short` — **80 PASS**, 38.43с.
