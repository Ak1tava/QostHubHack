# Т09: воспроизводимые демоданные

Набор полностью синтетический. Это сценарий демонстрации и проверок, не производственная история, регламент ремонта или доказательство качества модели.

## Запуск

Из services/api после миграций, в отдельной локальной PostgreSQL БД qosthub_demo_t09:

~~~sh
uv sync --locked
uv run alembic upgrade head
uv run python -m app.seed_demo --seed 42 --as-of 2026-10-04
~~~

DATABASE_URL задаётся вне Git. Хост разрешён только localhost/127.0.0.1/::1 или db внутри локального Compose. Имя БД должно быть qosthub_demo* или qosthub_test* без prod/production/live. Рабочая qosthub запрещена. URL должен быть без query-параметров; PGHOSTADDR/PGSERVICE/PGSERVICEFILE/PGOPTIONS запрещены, чтобы адрес/БД не переопределялись драйвером. Не переименовывайте рабочую БД ради обхода проверки.

Пароль вводится через getpass; для автоматического запуска DEMO_PASSWORD задаётся через окружение. Минимум 8 символов, без встроенного значения. Пароль не выводится и не сохраняется в файлы; хешируется отдельно для каждого аккаунта. Логины для примера: t09-42-2026-10-04-master-01, master-02 и worker-03..17 с тем же префиксом. Все 17 аккаунтов получают явно заданный демопароль. Повтор seed не меняет пароли.

PHOTO_STORAGE_PATH задаёт каталог хранения файлов. Seed создаёт PNG-схемы с текстовыми метаданными SYNTHETIC; это не настоящие фотографии ремонта. Конфигурация каталога должна совпадать с будущим T05 storage. Не используйте эти изображения для оценки качества зрения на реальных фото.

Команда запускается только явно, никогда при старте API. Существующий app.modules.auth.demo создаёт два простых аккаунта и не заменяет полный seed Т09.

## Состав и период

- 4 участка, 25 единиц оборудования, 3 бригады.
- 2 мастера и 15 исполнителей, разрешённые участки и смены.
- 20 шифров, 40 материалов, 125 синтетических норм.
- 500 нарядов: 450 закрытых и 50 в различных состояниях.
- Версии событий, отчёты, решения мастера, расход, PNG-схемы, интервалы работы/пауз/проверки и простоя.

История идёт от as-of минус три календарных месяца (день ограничивается последним днём месяца) до начала as-of, конец исключён. Для 2026-10-04: [2026-07-04 00:00, 2026-10-04 00:00) в UTC+05. Есть дневные и переходящие через полночь смены. Смены на дату снимка также добавлены для дальнейшей демонстрации.

Для одинаковых seed/as-of стабильны UUID, содержимое, даты и порядок. Парольные соли намеренно случайны: воспроизводимость истории не означает одинаковые секреты. Изменение seed меняет выборку; смена параметров на уже заполненной T09 БД отклоняется — нужен отдельный набор/БД.

Наряд либо индивидуальный, либо бригадный с ответственным. История соответствует переходам ядра Т03; закрытие подтверждено решением мастера. Оценки мастера на пятибалльной шкале C6. Историческая приёмка синтетическая, модель не вызывалась и фиктивные AIReview не создаются. В outbox история не записывается, чтобы будущий Telegram не рассылал сотни старых событий. Производственные действия продолжают пользоваться обычными сервисами Т03.

## Безопасность повтора

Импорт выполняется одной транзакцией с advisory lock PostgreSQL: два одновременных seed не дублируют набор. Пустой набор добавляется; полностью совпадающий возвращает unchanged. Частично загруженный или изменённый набор отклоняется. Данные других пользователей, пароли и существующие наряды не удаляются и не обновляются.

Созданные текущей транзакцией файлы удаляются при явном rollback; существующие файлы не перезаписываются. Изменённые/утраченные фото готового набора обнаруживаются. После аварийного завершения до commit могут остаться синтетические файлы; повтор проверит хеши и завершит импорт. БД и файловая система не образуют общую атомарную транзакцию. Для нового запуска используйте отдельную демо-БД и отдельный каталог файлов, не очищайте рабочие каталоги.

Loader load_dataset предназначен для доверенных данных build_dataset, не является API загрузки пользовательского JSON. Вызывающая сторона владеет commit/rollback.

## Эталон аналитики

catalog.json и scenarios.json — исходные синтетические справочники и настройки. expected_anomalies.json — только тестовый эталон для seed=42/as-of=2026-10-04:

1. 24 ремонта одного подшипникового узла.
2. 12 пар: ППР и аварийный ремонт того же оборудования в следующие 48 часов.
3. 12 расходов 3 единицы при сопоставимой норме 1.

Есть 24 обычных контрольных ремонта с отдельными парами оборудование/шифр, не повторяющимися в семидневном окне, и остальные фоновые случаи. Фон может иметь случайные повторы; эталон описывает заложенные группы, а не исчерпывающий список любых корреляций. Эталон содержит реальные UUID импортируемых сущностей. Т08 должен находить закономерности запросами/расчётами по БД; файл expected_anomalies запрещено читать из runtime аналитики. Для другого seed/as-of UUID другие: этот закреплённый эталон нельзя выдавать за ответ новой выборки. Повтор после ППР — наблюдаемая связь, не доказательство причины.

## Оценка ИИ и передача

32 размеченных случая в evals/cases.jsonl: 20 dev, 12 holdout. Правила использования и будущие метрики — evals/README.md. API модели не вызывался; results.md создаётся после реальных измерений Т07. SVG и PNG синтетические; реальные разрешённые фото требуют отдельной разметки.

Данные расположены в корне checkout. Текущие Dockerfile/.dockerignore не включают data/demo и evals; для контейнерного запуска A должен отдельно предоставить read-only data/demo в корне /workspace/data/demo и путь PHOTO_STORAGE_PATH с правом записи. Из контейнера /workspace/services/api корень тот же. Runtime API не требует этих данных, только явная команда seed.

Т09 не меняет frontend, HTTP-контракты, модели, миграции или manifests. Т07 подключает живую проверку/runner, Т08 — независимые расчёты, Т10 — проверку демо на телефонах.
