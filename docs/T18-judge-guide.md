# Проверка НарядAI судьями

Адрес стенда: **https://beatles-davidson-ricky-floors.trycloudflare.com** — организатор подставляет действующий адрес перед передачей судьям.

В судейском режиме выберите одну из трёх кнопок: **«Мастер»**, **«Рабочий 1»**, **«Рабочий 2»**. Пароли не нужны. **«Сменить профиль»** возвращает к выбору роли и завершает прежнюю сессию; для одновременной проверки используйте отдельные браузерные профили или устройства. Ключи OpenAI/Telegram и серверная конфигурация судьям не передаются.

## Подготовленные примеры и живой режим

Набор `prepared-v2` содержит три учебных наряда с фотографиями до/после и чек-листом. На результате виден один бейдж **«Подготовленный результат»**; в **«Подробностях проверки»** указаны происхождение и учебные изображения. Внешний ИИ при подготовке этих результатов не вызывается. Примеры демонстрируют поведение продукта и не доказывают производственную точность ИИ.

1. Выберите **«Мастер»**, откройте наряд. Блок ИИ-проверки расположен выше истории: сразу видны источник, вывод, доказательства, недостающие сведения и следующее действие. Сопоставьте заявку, отчёт и фотографии до/после; откройте ссылки на фото из доказательств. Три подготовленных примера показывают **соответствие заданию**, **доработку** и **недостаток доказательств**.
2. Источник различается явно: **«Результат ИИ»**, **«Проверка по правилам»**, **«Подготовленный результат»**, **«Тестовый результат»** или **«Источник не подтверждён»**. До сдачи отчёта карточка объясняет запуск проверки; после сдачи показывает ожидание или выполнение. Ошибка либо неопределённый источник не означают успешную ИИ-проверку.
3. Приёмка доступна только мастеру. Подтвердите приёмку или верните работу на доработку; для неопределённого результата требуется объяснение. Рабочий не закрывает свою работу. Сохранённое решение мастера видно в карточке проверки и истории.
4. В сценарии доработки рабочий начинает исправление, добавляет новые фото, проверяет чек-лист и сдаёт новый отчёт. Новая версия получает обычное задание настоящего ИИ; подготовленный результат не подставляется. Для проверки двух рабочих мастер назначает новый наряд выбранному рабочему; добавление второго профиля не переназначает старые наряды.
5. Проверьте голосовой ввод в создании или отчёте: только русская речь, редактируемый черновик, явная вставка. Смена RU/KZ меняет интерфейс и не переводит исходные записи.
6. Посмотрите историю, отчёты и рейтинг. Для статистической демонстрации используйте отдельный набор500; три подготовленных наряда не являются статистической выборкой.

Настоящий ИИ работает серверным budgeted consumer в прежнем общем лимите **$10**, включая ранее учтённые расходы. При ошибке или недостатке доказательств требуется решение мастера. Telegram доставляет сообщения после личной привязки получателя в PWA. Подготовленные сценарии не отправляют Telegram.

## Подготовка организатором

Выполнять из `services/api` в отдельной локальной синтетической PostgreSQL БД `qosthub_demo*` или `qosthub_test*` после миграций:

```powershell
python -m app.judge_demo --confirm-demo --cohort jury-2026 --as-of 2026-10-08 --scenario-set prepared-v2
```

Первую команду выполняют только при первоначальной подготовке группы. Она добавляет суффикс `-prepared-v2`; пароли базовых аккаунтов вводятся скрыто и остаются у организатора. Для существующей prepared-v2 группы после резервной копии добавьте второго рабочего:

```powershell
python -m app.judge_profiles --confirm-demo --cohort jury-2026
```

Команда сохраняет прежние пароли, идентификаторы, наряды, назначения и действия; повтор не сбрасывает данные. Полученные UUID задайте в `JUDGE_MASTER_USER_ID`, `JUDGE_WORKER_1_USER_ID`, `JUDGE_WORKER_2_USER_ID`; включите `JUDGE_MODE_ENABLED=true` и `JUDGE_COHORT=jury-2026` без суффикса. Подробности — [вход судей](judge-profiles.md). Режим выключен по умолчанию и доступен только трём активным профилям одной изолированной группы. Настройки БД и приватного хранилища находятся вне Git; legacy-v1 не меняется.

Повтор с той же группой и датой возвращает `unchanged`, сохраняет действия судей и пароли. Несогласованные данные или отсутствующие фотографии вызывают отказ. Для нового дня нужна новая группа; повтор не сбрасывает историю и не продлевает смену. Setup не подключает demo-provider к production и не изменяет бюджетный ledger.

Запуск и восстановление: [native runtime](mvp-native-runtime.md). Команды повышения прежнего бюджета повторять не нужно: действующий потолок уже $10. Ledger нельзя удалять, заменять новым или сбрасывать на рестарте.

Компьютер организатора должен оставаться включённым, подключённым к интернету и без перехода в сон. Для полного сценария нужны PostgreSQL, API, Nginx, Whisper, review/notification workers и cloudflared. После перезапуска Quick Tunnel адрес может измениться: организатор обновляет ссылку для судей и Telegram webhook. Единый запуск, статус и остановка — [native runtime](mvp-native-runtime.md).

Физическая мобильная приёмка отложена. Фактический SHA, команды и результаты — [проверка релиза](MVP-finalization-verification.md).
