# Независимая проверка НарядAI судьями

Организатор передаёт действующий **HTTPS-адрес PWA** и две отдельные пары логин/пароль: `judge-<группа>-master` и `judge-<группа>-worker`. Пароли передаются отдельно от публичной инструкции. OpenAI API key, `.env`, консоль и бюджетный ledger судье не требуются. Используйте два браузера/профиля для мастера и исполнителя.

Это **синтетический демонстрационный участок**: пять нарядов, условные отчёты, рисунки вместо фотографий ремонта. Безопасный резерв использует локальный тестовый provider без OpenAI и сохраняет явно подписанный **MOCK** с вердиктом «Требуется решение мастера». Он показывает структуру объяснений и ссылки на evidence; качество реального ремонта, скрытые узлы и безопасность запуска не подтверждает. Предварительно закрытые наряды показывают исторические решения демомастера, а не автоматическое закрытие ИИ. Пользователь разрешил настоящие OpenAI и Telegram на сервере с общим лимитом **$10**; организатор включает budgeted worker с сохранением прежних расходов в ledger. Ключи судье не передаются.

1. Войдите мастером и откройте наряд `T18-<группа>-04` в статусе ИИ-проверки: заявка и рисунок «до» → требования → сохранённый отчёт и рисунок «после». Требование реальных фотографий останется в ограничениях MOCK.
2. В блоке проверки просмотрите метку MOCK, объяснение, ссылки «Заявка», «Сохранённый отчёт», «Фото после работы» и ограничения. Это сохранённый результат **тестового provider**, не сохранённый реальный ответ OpenAI.
3. Только мастер выбирает приёмку с оценкой или возврат с причиной. Для приёмки результата `human_review` сервер также требует объяснение решения. Проверьте новый статус и событие в истории. Исполнитель не может принять собственную работу.
4. Исполнителем откройте `T18-<группа>-03` («Выдан»): примите, начните работу, сохраните свой отчёт/шифр/материалы и сдайте. На активном стенде серверный budgeted worker выполняет настоящую проверку OpenAI, Telegram доставляет уведомления после привязки аккаунта. При отсутствии worker/ключа новая ИИ-проверка остаётся ожидающей; обычный worker **без OpenAI ключа** показывает честное ограничение недоступности provider. Предустановленный MOCK для №04 остаётся резервным примером.
5. Посмотрите №05 («Доработка») и №01/02 («Закрыт»), решения и историю. В отчётах выберите период от трёх месяцев до даты набора: исторические показатели рассчитаны по этим синтетическим событиям. Пять нарядов не предназначены для доказательства статистических закономерностей на реальном производстве.

Аккаунты видят отдельный участок/оборудование. Мастер видит двух участников группы; исполнитель — себя и назначенные ему наряды. Справочники материалов и шифров общие по действующему контракту, поэтому стенд должен содержать только синтетические данные. Нет ролей admin/manager, доступа к чужим участкам или административных API. Выход отзывает сессию на сервере.

## Подготовка организатором

Запускайте из `services/api` на **отдельной локальной PostgreSQL БД** `qosthub_demo*` или `qosthub_test*` после миграций, с синтетическим содержимым и отдельным хранилищем фотографий:

```powershell
python -m app.judge_demo --confirm-demo --cohort jury-2026 --as-of 2026-10-08
```

Пароли вводятся скрыто, разные, по 12–128 символов; стандартных паролей нет. CLI не выводит секреты. `DATABASE_URL` и `PHOTO_STORAGE_PATH` задаются оператором вне Git. Setup не вызывает OpenAI/Telegram, не запускает consumers, не создаёт review jobs/outbox и не меняет бюджетный ledger. Его `SyntheticJudgeProvider` совместим с внутренним интерфейсом проверки, но не подключён к production worker.

Повтор с той же группой/датой сохраняет пароли и действия судей, возвращает `unchanged`. Изменение ролей/доступа/состояния аккаунтов, конфликт логинов/UUID, частичный набор или отсутствующие файлы вызывают отказ. Для нового демонстрационного дня создайте новую группу; повтор setup не продлевает смену и не сбрасывает наряды. Данные и фотографии перед демонстрацией копируются обычным резервным копированием стенда; фото не перезаписываются.

Перед передачей URL организатор проверяет вход с внешней сети, HTTPS/WSS, cookie Secure/HttpOnly/SameSite, CSRF, restart/readiness, отсутствие ключей в браузере/логах и работоспособность URL. Временный tunnel требует включённого компьютера. Эти живые проверки записываются отдельно; локальные API-тесты их не заменяют. Прежний ledger с расходами сохраняется; разрешённый общий лимит $10 контролируется сервером. Успех доставки Telegram подтверждается отдельно по фактической привязке/сообщению.

## Явное повышение прежнего общего бюджета

Остановите обычный и budgeted AI worker; используйте **прежний путь ledger**, настройки моделей/цен/лимитов токенов сохраняйте. Команда ниже только фиксирует разрешённое повышение, не вызывает provider и не требует OpenAI ключа:

```powershell
python -m app.workers.budgeted_reviews --live --ordinary-worker-stopped --ledger <прежний-budget.json> --budget-usd 10 --increase-budget-from 2
```

Исходный `frozen.json` остаётся неизменным. Рядом создаётся неизменяемый `*.budget-amendment.json` с прежним ledger и конфигурацией; calls, usage, reservations и расходы сохраняются. Изменение лимита простым restart запрещено. После успешного повышения обычный budgeted запуск использует `--budget-usd 10` и **не** повторяет `--increase-budget-from`. Новый лимит включает прежние расходы, а не добавляет $10 к ним.

При незавершённом платном вызове, неизвестной usage, provider error, ownership halt или частично записанном повышении команда отказывает; расходы не сбрасываются. Требуется аудит сохранённых файлов перед дальнейшей платной работой. Consumers блокируются одновременно файлом ledger и advisory lock базы; изменение конфигурации помимо подтверждённого бюджета запрещено.
