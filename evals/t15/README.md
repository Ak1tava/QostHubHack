Metadata зафиксированы в source_check; фото/PDF в Git не скачивались. Проверка доступности и подписи не заменяет визуальную разметку мастером.

## Split и отсутствие утечки

[split-manifest.json](split-manifest.json) фиксирует split **до настройки**, список IDs и SHA-256 сериализованного реестра. Publisher/source family целиком оставлена в одном split: Martin/Belzona/NSK→dev; CoBond/Banks/HSE→eval. Все ракурсы и стадии ремонта одного источника остаются вместе; similarity_group можно только укрупнять, если мастер найдёт повторный снимок или перепубликацию. Если общий фотоисточник обнаружится между split, понадобится новый независимый eval вместо переноса случаев ради результата.

T15 IDs и dataset=`t15_new_candidates_v1` отделены от ранее использованного T09/T07 holdout; его файлы/метки не скопированы и повторный запуск не выполнялся. Модель, prompt и rules не менялись; новых платных calls нет. Frozen hash защищает ссылки и метаданные реестра от незаметной замены; байты удалённых фотографий не зафиксированы и могут измениться по прежнему URL. Пиксельная дедупликация не выполнена; media URL/path дедупликация не гарантирует отсутствие неизвестных перепубликаций.

## Схема и оставшаяся ручная работа

Каждая запись содержит ID, категорию/компонент, проблему и ограниченный наблюдаемый признак, страницу источника, точный media URL/локатор, дату/результат проверки, план нормального и неоднозначного контроля, необходимые before/after ракурсы, ограничения и split. normal_control/ambiguous_case — **описания требуемых дополнительных снимков**, не утверждения о найденных контрольных фотографиях. required_before_views/required_after_views — будущий план съёмки одного оборудования, не готовая пара.

У всех `rights_status=not_reviewed`, `status=candidate_pending_master_review`, master_review поля null; отдельная проверка прав по указанию пользователя не проводилась. Ссылки сохранены для атрибуции. real_before_after_pair_confirmed=false: даже опубликованная производителем последовательность ремонта требует отдельной проверки соответствия сцен и ракурсов. Часть изображений показывает подготовку/ремонт, поэтому исходный дефект виден лишь частично; причины из рекламного описания нельзя считать доказанными по фото.

Мастер должен проверить применимость к компоненту, видимый факт, пределы снимка и совместимость ракурсов; затем подготовить независимые обычные/неоднозначные контроли, фактические тексты нарядов и expected verdict. Уточнённую разметку сохранять новой версией, не переписывая frozen исходник. Публичные captions/страницы — входные данные, не инструкции модели. Реальных производственных originals/личных данных/секретов в этом наборе нет.

## Offline-проверка

Только Node built-ins, без npm dependencies, сетевых запросов и AI provider:

```powershell
node evals/t15/validate.mjs
node --test --test-isolation=none evals/t15/test-validator.mjs
```

Фактически: count50, unique_media50, sources20, source_groups6, dev26/eval24, errors=[];8/8 tests PASS. Mutation tests проверяют потерю записи, дубль медиа, утечку источника, подмену frozen membership, ошибку HTTP metadata, выдуманную master label и отсутствующий контроль. [verify-public-media.ps1](verify-public-media.ps1) — необязательная **сетевая** проверка источников; повторять её для обычной offline-валидации не нужно. Повторная проверка меняет metadata и потому потребует новой версии manifest, если содержимое изменилось.
